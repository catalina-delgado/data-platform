Manejo de errores

Formato

Todos los errores de la API REST devuelven el mismo formato (estándar de FastAPI):

{ "detail": "descripción legible del error" }

detail es texto pensado para loguear o mostrar en un mensaje de error, no un código estable para comparar por igualdad — para decidir el flujo, revisar el status code HTTP, no el contenido de detail.

Códigos HTTP

400 Bad Request

mode en el body de un POST /v1/tables/{namespace}/{table} no es "append" ni "overwrite".

{ "detail": "mode debe ser 'append' u 'overwrite'" }

Cómo reaccionar: es un error del lado del que llama — corregir el body, no reintentar tal cual.

401 Unauthorized

Falta el header X-API-Key, o la key no existe / fue revocada.

{ "detail": "Falta el header X-API-Key." }
{ "detail": "API key inválida o revocada." }

Cómo reaccionar: revisar que el header se esté mandando y que la key siga activa (docker exec strategodata-api python manage_keys.py list). No tiene sentido reintentar sin cambiar la key.

403 Forbidden

Se intentó escribir (POST /v1/tables/...) con una key que no es de plan internal.

{ "detail": "Escribir requiere una API key de plan 'internal'." }

Cómo reaccionar: las keys free/pro son de solo lectura por diseño — no es un bug. Si el caso de uso realmente necesita escribir, conseguir una key internal (pipelines propios) en vez de reintentar.

404 Not Found

La capa, tabla, o combinación namespace.tabla no existe en el registro.

{ "detail": "No se pudo leer la tabla: Dataset 'gold.no_existe' no existe en el registro" }

Cómo reaccionar: confirmar el nombre exacto con GET /v1/namespaces/{namespace}/tables antes de leer. Un typo en el nombre de la tabla es la causa más común.

429 Too Many Requests

Dos causas posibles, distinguibles por el mensaje:

Límite de tasa (ventana de 60 segundos):

{ "detail": "Límite de tasa excedido (60 req/min en plan 'free')." }

Cómo reaccionar: esperar y reintentar — el contador se resetea al empezar el siguiente minuto. Si esto pasa seguido en producción, es señal de que hace falta un plan con más límite (pro), no de que haya que reintentar más agresivo.

Cuota mensual excedida:

{ "detail": "Cuota mensual del plan 'pro' excedida (1000000 requests)." }

Cómo reaccionar: reintentar no sirve hasta el mes siguiente (la cuota se resetea el día 1). Revisar GET /v1/usage para ver cuánto falta, y considerar un plan con más cuota si es algo recurrente.

500 Internal Server Error

Falló la escritura del lado del servidor (problema de conexión a MinIO o Postgres, datos malformados que pandas.DataFrame(records) no pudo convertir, etc.).

{ "detail": "Error al escribir: <detalle de la excepción>" }

Cómo reaccionar: sí tiene sentido reintentar (con backoff) si el error parece transitorio (timeout de conexión); si el detail apunta a un problema con los datos enviados (tipos inconsistentes entre filas, por ejemplo), hay que corregir el payload primero.

Resumen: ¿cuándo reintentar?

Código ¿Reintentar?
400 No — corregir el request.
401 No — corregir la key.
403 No — usar una key con el plan correcto.
404 No — corregir el nombre de la tabla.
429 (rate limit) Sí, esperando al siguiente minuto.
429 (cuota) No hasta el próximo mes, o subir de plan.
500 Con backoff, si se sospecha que es transitorio.

Errores usando strategodata_client en vez de la API REST

El cliente Python no traduce nada a códigos HTTP — deja subir las excepciones de Python tal cual (ValueError, excepciones de psycopg2 o s3fs). Ver manejo de errores del cliente.
