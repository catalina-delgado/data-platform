La mayoría de las plataformas obligan a elegir entre pagar de más por un warehouse sobredimensionado, o construir la infraestructura de datos a pulso, pieza por pieza.

StrategoData resuelve los dos problemas con una arquitectura pensada para eficiencia real, sin licencias infladas ni sobreingeniería. Esa eficiencia se traduce directo en un costo por request más bajo — y en datos limpios, listos para usar, sin que tu equipo tenga que operar nada.

La refinería

Tres niveles. Nada inventado para la página de venta.

Esta es la arquitectura medallion real que corre la plataforma — los mismos nombres aparecen en el registro de tablas, las rutas del API y los DAGs de Airflow.

Bronce
bronze.*

Crudo, tal como llega de la fuente. Solo se agrega, no se toca, con marca de tiempo de ingesta y origen para trazabilidad completa.

Plata
silver.*

Limpio, tipado, validado. Reglas de calidad aplicadas — nulos manejados, tipos convertidos — todavía sin lógica de negocio.

Oro
gold.*

Agregado y servido. Lo que consumen dashboards, reportes y entrenamiento de modelos a través del API — este es el nivel que expone el API.

Airflow programa y reintenta cada nivel de forma independiente — que bronce falle no obliga a re-ingestar oro.
Qué gestionamos

Una plataforma totalmente gestionada.

Tu equipo envía la data cruda (o conecta sus fuentes); StrategoData se encarga de la infraestructura, el linaje y el cómputo. El resultado se consume limpio, medido, vía API.

ALMACENAMIENTO

Nativo en parquet

Los datasets son parquet particionado plano sobre almacenamiento de objetos — sin servicio de catálogo Iceberg, sin formato de tabla de proveedor que licenciar u operar.

METADATOS

Registro en Postgres

Esquema, particiones y linaje de cada dataset quedan trazados en un registro liviano — visibilidad completa sin el costo de un servicio de catálogo aparte.

ORQUESTACIÓN

Airflow, no cron improvisado

Bronce, plata y oro son tasks independientes y reintentables en DAGs que se pueden leer, no un script que alguien corrió una vez desde su laptop.

CÓMPUTO

DuckDB y Polars

Las transformaciones corren embebidas, sin JVM ni cluster que mantener vivo — esa eficiencia de cómputo se traduce en un costo por request más bajo.

ACCESO

API REST medida

Cada key tiene un plan: límite de tasa, cuota mensual y alcance de lectura/escritura exigidos en cada request, no agregados después.

OPERACIÓN

Infraestructura gestionada de punta a punta

Almacenamiento, registro, orquestación y API corren de nuestro lado, sobre una arquitectura eficiente sin clusters redundantes. Ningún equipo de plataforma propio que armar ni mantener.

EN EL ROADMAP

Feature store para entrenamiento

Recuperación de features punto-en-el-tiempo para entrenar modelos, sobre las mismas tablas gold. No está construido todavía — lo decimos acá, no lo vendemos como si ya existiera.

EN EL ROADMAP

Portal de keys self-service

Hoy las keys se emiten por CLI. Un dashboard self-service para aprovisionar y ver consumo es el próximo paso.
